# 1.11.1 — Readable holding notes

Atomic holding imports now create filenames and titles such as `EXM — Example Bank Investing •1234` instead of an encoded account/security ID pair. Untickered investments use the supplied investment name. The full investment name and stable IDs remain in their existing properties; the title uses the currently configured title key.

The defect originated in `AtomicFinanceStore.writeSnapshot`: it used the identity pair as the filename and omitted a readable title. The fix changes that creation operation, reuses the existing safe-name/unique-path helpers, and immediately indexes newly created holdings. Root discovery reads unindexed notes when metadata is still pending, preventing immediate imports from creating another copy. Created positions are active immediately. Missing labels or account paths fail before holding writes.

Existing holdings keep their paths and edited titles during sync. Colliding filenames preserve the other note and receive the existing numeric suffix convention. Existing ID-named notes are not automatically renamed or assigned titles. There is no new watcher, repair sweep, cleanup command, persistent state, setting, property alias or schema migration. A requested one-time rename of existing notes is separate from the plugin change.

This is a backward-compatible patch. Minimum Obsidian remains **1.12.0**; Controller banking retains its own 1.12.3 requirement. The three settings destinations, default route, disclosures, commands, connection handoff and desktop/mobile controls are unchanged. Atomic-line records retain their current format.
