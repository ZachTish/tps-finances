# TPS Finances 7.0.1 — Ignore unrelated kind ambiguity

A vault-root dashboard could fail on a valid daily note with multiple kinds because it requested a global single-kind classification before deciding whether the note belonged to Finance. The reader now preflights configured Finance kinds and explicit legacy Finance identities. Unrelated notes stay outside Finance decoding; real Finance classification and identity conflicts still fail explicitly. No notes, user mappings, settings defaults or controls are changed by this patch. No repair, fallback catch, cache, watcher or additional scan is added.

Patch release; minimum Obsidian 1.12.0. All 344 inherited/new checks pass (7 retirement and 337 domain checks), including a 4,049-unrelated-note root dashboard regression with zero unrelated authoritative classifications, zero raw/cached reads and zero writes. Installed test-vault QA with actual GCM reproduced the global ambiguity but successfully read one account and transaction through Finance, also with zero raw/cached reads and writes. That installed check uses a scoped synthetic Finance folder. Saved Finance/GCM settings were unchanged and fixtures archived. The final separate production build, test deployment and targeted reload passed. No settings UI change; 7.0.0 native creation/settings acceptance remains applicable. Physical iPhone acceptance remains unverified.

Tested in Obsidian Plugin Test Vault; ready for BRAT pull. Production installation is a separate, explicitly authorized operation.
