# TPS Finances 3.0.0 — Kind-owned finance identity

When GCM has distinct configured kind-list values for ordinary transactions, investment transactions, and holdings, Finances now derives its internal record type from the decoded kind and omits the redundant authored `type` property. Provider imports and updates, manual cash entries, holding snapshots, dashboard reads, title logic, and budget classification use that same decoded identity. Finance fields such as `investmentType` and `holdingType` remain intact. GCM owns the kind paths and any discriminator; Finances does not hardcode a finance subtype path. If ordinary and investment transactions still share one configured list value, Finances retains their `type` discriminator rather than guessing from optional provider fields. A read-only GCM `type: transaction` alias can still identify legacy Wallet notes without reintroducing authored `type`.

Generated whole-note Transactions and Holdings Bases now filter on configured kind values. GCM v2 Base generation emits primary kind predicates without legacy tag or scalar aliases. Finance readers still accept configured aliases, but old-only notes no longer appear in newly generated Bases. This **major** release therefore requires a coordinated migration of existing Finance notes and Bases before installation in vaults that still depend on legacy classifications. Customized Bases are not rewritten by the plugin. Historical inline transaction and finance-snapshot `type` formats are unchanged. No automatic migration, startup scan, background repair, or new Finances setting is added. Minimum supported Obsidian remains **1.12.0**.

## Validation

- Focused regression tests cover distinct and shared configured kind values; type-free provider, manual, and holding creation; dashboard reads; retry/no-op writes; legacy type removal during a direct edit; a read-only Wallet alias; generated Base filters; and ambiguous-classification failure.
- Full versioned `npm test`: 2 connection checks and 379 Finance checks passed; TypeScript validation and the production bundle build passed. The test command used `TPS_NO_DEPLOY=1` so it did not replace the shared runtime during parallel QA.
- A separate `npm run build` deployed byte-changed `main.js` and `manifest.json` to Obsidian Plugin Test Vault; source and installed hashes match, and Finances `data.json` stayed byte-identical. The reloaded Properties page showed the updated explanation for the legacy `type` key without saving any setting. The dashboard command opened, but a pre-existing Test Vault cash transaction with a missing account link prevented a populated dashboard UI check; the type-free dashboard model passed the synthetic regression. No provider call or manual record creation was made in UI QA.
- No live provider import was performed for this release. The Mac v0.2 note and Base migration is a separately guarded deployment.
