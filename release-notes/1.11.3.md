# TPS Finances 1.11.3

Opening or refreshing the dashboard did unnecessary work on unrelated notes: atomic candidate discovery decoded every configurable field to check a fixed identity key, and legacy discovery split every body into lines even when it could not contain a transaction.

The fixed `financeId` field now supplies candidate selection directly. Configuration/migration and identity-key validation still runs before discovery, and each candidate still uses the current-source decoder. Legacy indexing skips line splitting when its required marker is absent, after clearing obsolete ownership. Reads, accepted records, configured property names, folder metadata-delay behavior, duplicate precedence and existing atomic write guards are preserved.

This is a backward-compatible patch. There is no new cache, watcher, timer, retry, recovery logic, setting or data migration. Settings destinations and commands are unchanged. Minimum Obsidian: **1.12.0**.

## Validation

- Six focused regressions; two failed before correction. Coverage includes unchanged/burst operation counts, stale metadata/current mapped fields, metadata delay, migration/configuration guards, and removal/reinstatement of legacy ownership.
- 107 focused checks and all 280 declared tests pass; zero failures or skips. TypeScript and the separate production build pass and deploy only to the test vault.
- Named plugin reload verified 1.11.3 and unchanged `data.json`. All consumer plugins remained enabled; no provider, sync or note-writing action was invoked.
- Two actual foreground warm dashboard opens per build: **1,067–1,129 ms → 784–869 ms**. Candidate discovery's synchronous portion: **140 ms → 18–19 ms**. Summed synchronous legacy indexing time: **65–66 ms → 12–13 ms**.
- Budget selection remained local: 49 ms, zero model loads or cached reads. Monitored settings/artifacts were unchanged within each run, and previous views/window geometry were restored.

The roughly 14,700 cached reads and seven Markdown enumerations remain. Counts differ by one Markdown file after adding these release notes. Trace-wide raw reads include unrelated work during operator dwell and are not attributed to the dashboard. The PerformanceObserver reported no long tasks, but the separately measured 140 ms synchronous baseline still demonstrates blocking work; absence of observer entries is not proof that no task blocked the UI. Timing samples are instrumented, warm, desktop-only and small. They do not establish physical iPhone, cold-process or production speed, or the broader native-performance target.

Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. Production installation and device acceptance are separate and are not claimed. The packaged Obsidian 1.14.2 duplicate Markdown-load issue is separate and is not patched by this release.
