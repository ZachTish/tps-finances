# TPS Finances 0.5.5

TPS Finances `0.5.5` is a backward-compatible Transactions Sync reliability release. It replaces unbounded text-matched pagination recovery and permissive malformed-page coercion with a bounded, structured, fail-closed state machine while preserving every successful finance workflow.

## What changed

- `TRANSACTIONS_SYNC_MUTATION_DURING_PAGINATION` is recognized only from `PlaidApiError.code`, after at least one page of the active attempt was accepted.
- Recovery restarts the whole update from its original durable cursor, as Plaid requires, with at most two automatic restarts.
- Every attempt is limited to 100 pages using Plaid's maximum 500-record page size.
- `has_more`, `next_cursor`, added/modified/removed arrays, row shapes, provider IDs, account IDs, transaction amounts, transaction dates, and pending-state booleans are validated before a page is accepted.
- Continuing cursors must advance. Cursor cycles, terminal rewinds, stationary terminal cursors carrying changes, and empty terminal cursors after update activity fail closed.
- A terminal empty cursor with no changes remains supported. If the Item already has a durable cursor, that checkpoint is preserved.
- Each page is normalized into compact attempt-local arrays and a new-identity overlay. Existing durable identities are read in place, and only newly created mappings are committed after a valid terminal page, so discarded or failed attempts cannot leak partial identities.

## Preserved behavior

- Initial and incremental Transactions Sync, additions, modifications, removals, signed amounts, categories, stable IDs, cursor persistence, and atomic Markdown application are unchanged for valid responses.
- Plaid connection, account synchronization, optional Investments handling, settings, commands, dashboard output, note formats, and SecretStorage contracts are unchanged.
- No setting or data migration is required.
- Minimum supported Obsidian version remains `1.12.0`.

## Before and after evidence

- Exact released `0.5.4`: all 28 declared checks passed.
- Against the released implementation, the new safe targeted gate passed only 3/8 quick pagination probes; five failed on leaked identities, text-matched recovery, malformed-field acceptance, and partial-state commits.
- The released repeated-mutation loop completed eight provider requests and attempted a ninth before the synthetic runaway guard stopped it. The candidate stops after six requests: three bounded two-page attempts.
- A failed 100-page released attempt left 101 generated identity mappings in shared state. The candidate commits zero mappings from the failed attempt.
- Candidate focused pagination/source contract: 12/12 passed, including seventeen malformed/non-progressing response cases, three valid terminal no-op shapes, and a deterministic 20,000-entry fixture that rejects enumeration of durable identity history.
- A local 100,000-entry benchmark measured about 41.07 ms median for the rejected full-map copy versus about 0.0001 ms for committing an empty overlay. This is a focused data-structure benchmark, not an end-to-end Plaid or Obsidian timing.
- Final declared suite: 37/37 passed, followed by TypeScript, the suite's production build, and the mandatory separate final build.
- Obsidian 1.12.7 reloaded the isolated test-vault runtime and rendered the disconnected Finances dashboard. No Plaid request, connection, setting change, note mutation, or production access occurred.

## Known limitations

- Plaid prescribes restarting after a mutation-during-pagination error but does not define a retry ceiling. TPS Finances allows two automatic restarts and then surfaces the structured provider failure; a later user-initiated sync starts again from the unchanged durable cursor.
- The 100-page limit is unchanged from previous releases and caps one attempt at 50,000 provider updates.
- Live Plaid was not called during QA. Tests use contract-shaped mocked responses so no credential, subscription, or institution traffic is involved.
