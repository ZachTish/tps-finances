# 1.11.2 — Responsive dashboard controls

Switching Overview/Budget, choosing a budget month or currency, and expanding budget transactions now redraw the data already displayed. Previously these local controls called the full data loader, rebuilding the transaction index and rereading Markdown bodies to discover legacy finance lines.

The fix extracts the existing paint operation. Open, record invalidation and explicit refresh retain the existing fresh-data queue. When a refresh completes, it paints its newest data using the current route and replaces old control closures. Focus, scroll, closed-view guards, budget calculations and mutating action owners are preserved. There is no new persistent cache, watcher, timer, setting or migration. Initial loading and real refreshes still perform the existing native/legacy discovery.

This is a backward-compatible performance patch. Minimum Obsidian remains **1.12.0**. Commands, configuration, record formats and mobile behavior are unchanged.

## Validation — September 28, 2026

- Five of eight new render-ownership checks failed against the old code; all eight pass with the fix. Coverage includes 50 local route switches, month/currency/expansion, focus/scroll, fresh model replacement, changes during an in-flight read, queued real invalidations, action ownership and close/error behavior. The actual dashboard and budget renderers run against a small DOM facade; unrelated painters and Obsidian base APIs are stubbed.
- Focused dashboard/budget checks: **35 passed**. Final versioned full `npm test`: **274 passed, zero failed or skipped**, including TypeScript and build validation.
- Separate production-mode build deployed the versioned artifacts to Obsidian Plugin Test Vault. Obsidian restarted during the reload handoff; that interrupted attempt was excluded. The newly running test app loaded **1.11.2** and completed the actual UI checks below. A final documentation-only build preserved the verified artifact bytes.
- Actual foreground UI clicks with installed consumers enabled: Overview→Budget **968 → 51 ms**; Budget→Overview **1,018 → 39 ms**; repeat Budget **915 → 18 ms**. Every old route click performed one model load and **14,214 cached body reads**; new clicks performed **zero model loads and zero cached body reads**. One new phase included 124 unrelated background raw reads; counts are not a claim that all plugins were idle.
- The month changed September→August in **14 ms**, without model loads or cached body reads, and focus remained on the month control. The old month phase did the same full reload but ended unfocused, so its timing is excluded from the foreground comparison. The after-run left sidebar was temporarily collapsed to expose the controls and restored; the changed layout limits strict timing comparability, while the eliminated model/read counts directly confirm the fix.
- A first dashboard open after app restart still took **3,011 ms**, with 14,214 cached read calls and 10,564 raw reads; a later real refresh took **892 ms**, with one model load and the same cached-read count. This patch does not optimize initial data discovery. There were no observed long tasks or note mutation events in these samples.
- Plugin settings and artifacts were byte-identical across the UI run; the QA dashboard closed and the prior view was restored. No outbound sync action, provider request, fixture note creation or production change was used. Currency and transaction expansion were covered by tests, not installed UI actions, because the test budget offered only USD and no configured rows.
- Physical iPhone testing and a plugin-free native baseline remain outstanding. These results do not establish the broader 80% native-performance target or production timings. Tested in the test vault and ready for the user's BRAT pull.
