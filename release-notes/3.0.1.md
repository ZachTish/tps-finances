# TPS Finances 3.0.1 — Failed dashboard source ownership

Test-vault-validated, backward-compatible performance patch.

A dashboard that encounters invalid Finance data now retains the files that contributed to or blocked that read. Unrelated note edits, renames, and deletions no longer trigger a full model rebuild merely because the dashboard displays an error. The error stays visible, and no invalid record is ignored or repaired. Readers record candidate or failing paths before duplicate-identity, invalid-transaction, metadata-decode, and budget-read failures can discard their dependency information.

Correcting, deleting, declassifying, or moving a blocking source, adding a relevant Finance record, and explicit owner/settings refreshes still request the existing render queue. Cold or in-flight reads and failures before any file source is known remain conservative. Successful models keep their source ownership. This adds no persistent cache, watcher, timer, retry, setting, note migration, or writer. It is a backward-compatible patch; minimum supported Obsidian remains **1.12.0**.

The candidate preflight no longer treats a body-only `[financeId::` example or legacy-only `type: financeTransactions` ledger as a new dashboard record. The whole-note reader does not consume those retired formats; explicit legacy review/conversion remains available. Actual Finance fields, holding and snapshot types, configured reader sections, and existing source dependencies retain their triggers.

## Validation

- Before the dependency fix, the first 15 focused cases produced 8 expected failures and 7 passes. Before the retired-candidate fix, four success/error burst cases each performed 21 model reads instead of one, and the revised legacy-positive regression also failed. The finished regression file contains 24 checks, including actual-reader duplicate deletion, invalid-transaction declassification, metadata-decode deletion, malformed-budget repair, and missing-cash-account recovery. Controls cover relevant edits, file/ancestor rename, new candidates, explicit refresh, in-flight events, unknown-source failures, and no spontaneous retries. A 1,000-ordinary-note fixture performs no further reader enumeration, metadata lookup, or source read during 20 unrelated edits after its cash-link error. Actual reader tests in root/folder and metadata/source modes exclude retired-only candidates while active Finance candidates still invalidate. Obsidian/event/UI boundaries are in-memory facades; the budget parser facade uses JSON as a YAML subset, not Obsidian's runtime parser.
- The focused dashboard suites passed 54 checks. Versioned `TPS_NO_DEPLOY=1 npm test` passed 405 checks (2 connection plus 403 Finance), with no failures or skips, followed by its TypeScript-checked bundle build. A separate `TPS_NO_DEPLOY=1 npm run build` also passed after the final source/README changes. Both preliminary builds reported `target=none reason=TPS_NO_DEPLOY`. Independent reviews found no blocking issue in the dependency boundaries or retired-candidate removal.
- Installed **3.0.0 before**: the existing Test-vault cash-account validation error left the view's source boundary unknown. Three separate body-only edits of one UUID plain note each generated two own vault events (modify and metadata), no other vault events, and one Finance model read. All-plugin metadata calls were 16,757–16,818 per edit; those totals are not attributed solely to Finance. Quiet idle produced zero events, model reads, and metadata lookups. Note creation was noisier and is not the comparison sample. Wrappers were restored, settings stayed unchanged, and the exact fixture contents were archived. No invalid finance record was repaired and no provider was called.
- A separate normal build deployed only main.js and manifest.json to the Test vault. The targeted disable/loadManifest/enable cycle loaded **3.0.1**; the plugin's normal unload detached its dashboard, so the previously open view was reopened through its existing action before the after capture. No data repair or import was performed.
- Installed **3.0.1 after**: the existing cash-account error now retained its dependency paths. Creating the plain UUID fixture and all three subsequent body-only edits caused **zero Finance model reads**. Each edit had two own events and zero other vault events, with 227–282 all-plugin metadata lookups; quiet idle again did no work. The original error remained visible. Exact fixture bytes were preserved and archived, all wrappers were restored, and Finance/GCM/Navigator settings matched the before hashes. GCM was also advanced from 7.3.8 to 7.3.9 between captures; its intervening change targets mobile layout and listener teardown. All-plugin counts are context, not a sole-Finance CPU attribution or speed claim.
- A final documentation rebuild retained the SHA-256 hashes below. The host window was hidden/unfocused, so no foreground, physical iPhone, Windows, or production latency claim is made. This test-vault change does not install anything in production; publication is the user's BRAT handoff.
