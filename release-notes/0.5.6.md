# TPS Finances 0.5.6

TPS Finances `0.5.6` is a backward-compatible dashboard performance and reliability release. It removes a guaranteed duplicate refresh and accidental fallback retry from the view-level action wrapper while preserving every released command, mutation, notice, and finance-data contract.

## What changed

- Dashboard Connect, Sync, and all three per-account transaction-route choices continue awaiting their existing action-owned refresh.
- The shared action wrapper now handles only rejected actions; it no longer starts another full dashboard render after the successful action has already refreshed the view.
- Connect records whether Sync was already active immediately before invoking it. The normal path uses Sync's one refresh; the busy early-return path performs one explicit refresh for the newly persisted Item instead of relying on the unrelated active run to finish.
- Successful self-refreshing actions perform one model read and one DOM commit instead of two.
- Sync paths that return without changing state perform no dashboard read instead of one.
- A failed action-owned model read remains visible instead of being immediately hidden by an undocumented second attempt.
- A source-backed call-path contract limits the wrapper to the six current self-refreshing call sites, so a future non-refreshing action requires an explicit test/contract decision.

## Preserved behavior

- Connect still completes Plaid Link, creates the Item, runs the initial Sync when available, preserves the existing busy-Sync Notice, and refreshes the dashboard exactly once through either branch.
- Sync still refreshes after provider and storage work, including partial institution failures that are reported to the user.
- Per-account default, daily-note, and account-note choices still reroute identified transactions and refresh after the reroute.
- Rejected actions still create one Obsidian Notice with the user-facing error.
- Commands, buttons, settings, Plaid requests, finance records, routing, classification, budgets, snapshots, and pagination safeguards are unchanged.
- No setting or data migration is required. Minimum supported Obsidian version remains `1.12.0`.

## Before and after evidence

- Exact released `0.5.5`: all 37 declared checks passed.
- The four new real-view action-path probes failed 0/4 against the released implementation.
- A successful self-refreshing action produced two sequential model reads and two DOM commits before this patch; the candidate produces one of each, a 50% reduction in that work.
- A no-op action produced one model read and DOM commit before this patch; the candidate produces zero.
- The released wrapper silently retried an action-owned render error; the candidate retains that error in the view and does not add a fallback attempt.
- An adversarial review found that Connect could persist a new Item while `syncAll()` took its already-running early return. A bundled real-main regression now proves both normal and actual busy branches refresh exactly once and preserve the existing Notices.
- Candidate focused action-path gate: 5/5 passed.
- Final declared suite: 42/42 passed, followed by TypeScript, the suite's production build, and the mandatory separate final build.
- An independent adversarial re-review approved the immediate pre-Sync busy-state capture, normal/busy refresh ownership, call-site closure, scheduler interaction, and preservation of failure behavior.
- Obsidian 1.12.7 reloaded the isolated test-vault runtime and rendered the disconnected Finances dashboard. No Plaid request, connection, Sync, setting change, note mutation, or production access occurred.

## Known limitations

- Live Plaid actions were not invoked during QA. The action wrapper and scheduler are tested through the real compiled view with deterministic model reads, DOM commits, failures, no-ops, and call-path source contracts.
- External metadata-triggered refreshes still use the existing serialized/coalescing dashboard scheduler and are intentionally independent of action ownership.
