# TPS Finances 1.15.0 — Record classification settings handoff

**Settings → Properties** now opens GCM's record-classification controls directly. Finance field-name settings no longer imply that renaming the `kind` key changes a record from tag storage to property storage. GCM remains the single owner of that choice. Finances continues reading and writing through GCM's live classification mapping for imports, manual entries, updates and dashboard records.

The additive `api.classificationBases` preview lets GCM 4.1.0 migrate only Finance Bases whose complete content still matches a generated definition. Customized Bases are preserved. A format change is blocked when the Finance `tags` or `kind` field name has been customized in a way that conflicts with GCM's core classification keys; those names can be restored through Finances' existing confirmed property-name migration first. Finance also rejects a target subkind property that overlaps any canonical or configured Finance field name or record identity key, ignoring case, so future writes cannot replace that data. Stable Finance IDs, atomic-line records and account matching are unchanged. No new persisted Finance setting, automatic note repair or startup scan is added.

This is a backward-compatible **minor** release. Minimum Obsidian remains **1.12.0**. Install this release before applying a Finance classification change in GCM 4.1.0. Tested in **Obsidian Plugin Test Vault** and ready for the user's BRAT pull; production was not modified.
