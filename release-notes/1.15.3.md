# TPS Finances 1.15.3 — One dashboard file snapshot per model

In **Atomic notes only** mode, each Finance dashboard model now enumerates Markdown files once and shares that file list plus lazily decoded metadata across its snapshot, account, holding, transaction, rule, and budget readers. This reduces repeated full-vault enumeration and metadata decoding when displaying a large whole-note transaction history. Atomic transaction discovery still checks current metadata for both candidate selection and inspection; source/API reads and every write retain their existing current-source checks. The change adds no persistent cache, watcher, new setting, automatic migration, or note rewrite.

In synthetic 10,000-transaction fixtures, the metadata-backed model used one file enumeration and zero note-body reads, with 30,000 metadata lookups at the vault root or 10,000 in a configured Finance folder. Version 1.15.2 used six enumerations and 70,000 or 10,000 lookups respectively. With 90,000 indexed unrelated notes, one model still performed 180,003 root lookups or 90,001 configured-folder lookups because cross-vault transaction discovery remains supported. These operation counts are from an in-memory harness and do not establish installed desktop or mobile latency. The selected direct classification save still avoids a full scan, but its dashboard refresh rebuilds an O(N) model; a later metadata event can cause a second build.

The default **Include inline entries** mode still has its separate legacy line-discovery scan. **Atomic notes only** requires the existing fresh marker audit; this test vault still has markers in QA fixtures and source examples, so installed UI verification retains Include inline entries. Unindexed arbitrary-name root transactions and ambiguous root budgets may still require body reads. A note created after a model captures its file list appears in the next model; Obsidian's metadata event schedules that rerender for an open dashboard. A stale non-null ordinary metadata entry can remain hidden until Obsidian refreshes its index. No existing inline data is changed. Minimum Obsidian remains **1.12.0**.
