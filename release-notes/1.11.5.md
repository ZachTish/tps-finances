# TPS Finances 1.11.5

Unrelated renames inside the finance destination rebuilt the entire dashboard. At the vault root this applied to every rename, including attachments. At the same time, removing a note's last finance marker or a legacy transaction line could leave stale rows because the old source was no longer recognized by current metadata.

Each open dashboard now owns a set of source paths gathered during its existing model reads. Change events consult those paths to recognize removals, moves and deletions. Current metadata, legacy inline content and configured storage sections identify possible new contributors. Unrelated changes skip model loading; genuine changes continue through the existing render queue.

The set contains paths only, is replaced with each successful model and is discarded on close. Collection adds no reads or scans. In-flight reads and error views conservatively accept Markdown invalidation until a complete model is available. No new watcher, timer, content cache, background maintenance, settings, migration or write path is introduced. Sync and property migration still own their final refresh. Public model results and existing no-argument API calls are unchanged. This is a backward-compatible patch; minimum Obsidian remains **1.12.0**.

## Validation

- Twelve new regressions; eight failed before correction. Coverage includes 50-event unrelated and in-flight bursts, classification/legacy removal, mapped keys, label-only accounts, new storage candidates, old paths, folder/extension transitions, close/error behavior and actual-reader source collection with identical model results and I/O counts.
- 46 focused checks and all 298 declared tests pass; zero failures or skips. Two existing source-inspection assertions were updated for the optional collector argument and equivalent sync guards; behavioral guard coverage remains. TypeScript and the separate production build pass.
- Test-vault deployment and named reload verified 1.11.5 and unchanged settings. Installed real readers/render queue and API file operations reproduced the originating defects before the fix.
- Unrelated rename: **1 → 0 model loads**, **9 → 0 Markdown enumerations**, **14,742 → 1 trace-wide cached reads**. The remaining cached read is outside a finance model load. No raw reads were observed in that after-action window.
- Atomic amount editing remains correct. Removing/restoring atomic classification or a legacy inline line now removes/restores its displayed row, with one model load per genuine change. Previously removals made no model request and left stale entries.
- Four synthetic files per run were directly archived and verified byte-identical to their final test contents. Five monitored disk settings files and Finances memory settings were unchanged after restoration; the test view was closed and all probes were removed. Final documentation build retained the tested runtime bytes.

The installed check used a temporary synthetic finance destination with all consumers enabled. It exercised real API mutations and rendered DOM, not pointer gestures or UI latency. Before actions were foreground; after actions were unfocused, so no timing comparison is claimed. Trace-wide reads can include other enabled consumers. First dashboard loading and genuine refreshes still perform the existing full legacy discovery; this release does not remove that work. Physical iPhone, true cold-process startup, production speed and the broader native-performance target remain unverified.

Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. Production installation and user/device acceptance are separate and are not claimed.
