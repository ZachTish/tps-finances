# TPS Finances 1.15.2 — Targeted atomic classification and readable summaries

In **Atomic notes only** mode, categorizing a transaction selected from the Finance dashboard now checks and updates its displayed atomic note directly. A missing, moved, replaced, reidentified, or newly reclassified note fails without changing another file. This removes the full transaction index read from that save, including for manual cash records. Plain ID-only callers and **Include inline entries** continue using the existing lookup and inline fallback. A duplicate identity added after the row was rendered is discovered by a later full index read or sync once both notes are visible, rather than by this targeted save. The save still enters the atomic frontmatter mutation for an unchanged submission to verify current source.

The Home summary now uses Obsidian's metadata-backed display model, avoiding one body read per indexed atomic transaction. In a configured Finance folder, transaction indexing skips a metadata preflight for files already under `Finances/Transactions`; inspection still verifies each candidate once. Overview and Home metric cards have wider responsive minimum widths and wrap full amounts and labels instead of displaying ellipses.

These changes are backward-compatible and add no setting, record migration, cache, watcher, retry, or automatic repair. Minimum Obsidian remains **1.12.0**. The default **Include inline entries** mode still discovers legacy lines on normal model loads. **Atomic notes only** requires its existing fresh marker audit; the current test vault has legacy markers, so installed UI verification will retain Include inline entries. Full dashboard refreshes still rebuild the model. In synthetic 10,000-note fixtures, the isolated selected save had zero vault enumerations, metadata/body reads and one frontmatter mutation. One metadata-backed refresh then performed six enumerations with 10,000 metadata lookups in the configured folder, or 70,000 lookups at the vault root, and zero body reads. These in-memory operation counts do not establish installed desktop or phone latency.
