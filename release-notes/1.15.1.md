# TPS Finances 1.15.1 — Manual classification honors Atomic notes only

Categorizing a manual transaction from a stale dashboard row could bypass the selected transaction-discovery mode. If its atomic note was missing, the classification action built a store with the default **Include inline entries** mode, scanned Markdown bodies for the same ID, and could edit an inline record even when **Atomic notes only** was selected. The action now passes the configured mode to that store. A missing atomic note reports an error without a legacy scan or write in Atomic notes only; Include inline entries retains its existing fallback.

This is a backward-compatible patch to the existing classification action. It changes no record format, stored setting, note, provider request, or migration behavior. Explicit conversion still scans inline entries. The Atomic notes only setting still requires a fresh full-vault marker audit before activation; a later external inline entry is hidden until Include inline entries is selected again. The root budget reader may independently read ambiguous note bodies, and normal dashboard models still process every atomic transaction. Minimum Obsidian remains **1.12.0**.
