# TPS Finances 0.5.2

TPS Finances `0.5.2` is a backward-compatible snapshot-read efficiency patch. Holding parsing reuses the account model already read for the snapshot, and latest-snapshot selection keeps one best candidate instead of sorting every matching file.

## Changes

- Holding account-link resolution builds its path-to-ID map from the supplied parsed accounts instead of rescanning all Markdown files and rereading account metadata.
- Latest-snapshot selection preserves the same descending frontmatter-date and path tie-break order with one maximum-selection pass.
- Holding ownership/currency, snapshot contents, settings, persisted finance records, and Plaid behavior are unchanged.

## Performance evidence

- Snapshot parsing removes a redundant full-vault account scan.
- Latest-snapshot selection changes from vault filter plus `O(S log S)` sort to one `O(V)` pass with one metadata read per candidate.
- A 100,000-case randomized dense selector matched the former ordering exactly.
- A synthetic 10,000-snapshot selector benchmark improved from about 113.72 ms to 19.61 ms over 30 iterations.
- Only local map/maximum-selection variables were added; there is no cache, persistent state, fallback, timer, or background task.

## Validation

- `npm test`: all 24 declared tests passed.
- Source-backed regressions verify parsed-account reuse, one-pass selector structure, and exact date/path selection equivalence.
- A separate final `npm run build` passed and deployed only to `.obsidian/plugins/tps-finances` in the isolated test vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**; Finances commands registered and the disconnected dashboard rendered.
- No Plaid connection or sync ran, no setting changed, and runtime-owned `data.json` remained absent.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- Latest-snapshot selection still inspects the vault's Markdown file list; this patch intentionally adds no index or cache invalidation.
- Populated-dashboard and live Plaid behavior remain covered by existing mocks and earlier QA rather than new live-provider calls.
