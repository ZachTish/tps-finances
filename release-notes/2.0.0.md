# TPS Finances 2.0.0 — Whole-note-only transactions

Transactions now use individual Markdown notes for provider sync, Apple Wallet import, manual cash entries, dashboard and Home display, public dashboard reads, classification, and the Transactions Base. The record-format, transaction-discovery, and daily-note/account-note routing controls are removed. Existing inline entries remain in their notes, but no active reader or normal writer uses them. Account `transactionLogTarget` values and their configurable property-name mapping remain stored for compatibility and have no routing effect. This removal of supported storage modes is a breaking change; minimum Obsidian remains **1.12.0**.

An explicitly saved old `recordMode: atomic-line` or `legacyTransactionDiscovery: discover` pauses new transaction writes, including provider/Controller sync and Apple Wallet import. **Settings → Data & storage → Legacy inline transactions** explains the pause and offers **Check old entries** and **Convert to transaction notes**. The check freshly counts inline `[financeId::` markers across Markdown files only when requested, reports the first path, and changes no notes. A zero-marker check clears the old review markers and resumes writes. Conversion remains a separate user action: each transaction note is written and verified before the exact old line is replaced with a link; unresolved lines remain for review. There is no startup vault scan, automatic conversion, deduplication, or repair.

Settings files missing both legacy keys are treated as whole-note mode so a working installation is not blocked by missing metadata. Such a file cannot reveal whether old inline entries still exist; run **Check old entries** before the next sync if the vault may contain them. Historical inline examples, malformed markers, and duplicate IDs require manual review. The check intentionally counts markers in examples and code, except verified conversion provenance. Customized Base contents, other settings, provider connection state, IDs, and existing note bodies are preserved.

## Validation

The versioned declared suite passed **366/366** checks (2 connection and 364 plugin) with no failures or skips. Focused regressions cover missing-key settings, old-setting write gates before provider requests, marker review and interrupted conversion, classification without inline fallback, duplicate atomic IDs, and a 10,000-unrelated-note dashboard model with zero cached body reads. The declared suite and a separate TypeScript-checked build first ran with `TPS_NO_DEPLOY=1`; the final normal build deployed the same versioned `main.js` and `manifest.json` to **Obsidian Plugin Test Vault**, with `styles.css` already byte-identical. The installed files match the tested source artifacts.

Hot Reload showed the installed Finance dashboard and **Data & storage** settings. The old Record format, Transaction discovery, and routing controls were absent; the explicit check/convert actions were present. A synthetic **Add → Cash account**, then **Add → Cash transaction** flow created one transaction note in `Finances/Transactions`, increased that folder's Markdown count from 1,694 to 1,695, and displayed the entry in Overview. Its `financeId` and other fields were in frontmatter; neither that note nor its account had an inline `[financeId::` entry. Both temporary QA notes were moved directly to `_archive` afterward. Finance runtime `data.json` remained byte-identical at SHA-256 `33700aadd6706871019cc57ef21aa0a864420f78bdbe4e1f50e130394ca36404`. No provider sync, Apple Wallet import, physical iPhone test, or production access occurred.
