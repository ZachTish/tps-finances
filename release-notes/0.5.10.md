# TPS Finances 0.5.10

TPS Finances `0.5.10` is a backward-compatible dashboard performance and reliability release. Account cards and transaction account labels now come from one invocation-local account-note scan instead of two independent full Markdown traversals.

## What changed

- `getDashboardModel()` creates an empty invocation-local label map and asks its existing account reader to fill that map while building account cards.
- The account reader walks the Markdown list directly and skips non-account paths in place instead of allocating an intermediate filtered array.
- The standalone `accountLabelsByPath()` rescan is removed.
- The snapshot-selection scan remains independent because it selects a different file collection and preserves the existing snapshot contract.
- Sync still calls the account reader without a label map, so it does not construct labels it cannot use.

## Preserved behavior

- Account-card order remains type rank, institution, then account name.
- Account balance, availability, currency, route ownership, holding ownership, holding currency, and snapshot-date semantics are unchanged.
- Transaction account display remains `name •mask` when a mask exists. Search text remains institution, name, mask, and filename in the same order.
- `accountName`, then `title`, then filename remains the name fallback order.
- Case-insensitive `.md` path removal is unchanged.
- An account note without `financeAccountId` still labels and classifies referenced transactions but does not become an account card.
- Rule matching still consumes the resolved account-search text, and manual/rule/provider/uncategorized classification precedence is unchanged.
- Commands, settings, Plaid requests and cursors, finance note formats, device state, budgets, dashboard actions, and minimum Obsidian `1.12.0` are unchanged.
- No settings or data migration is required.

## Before and after evidence

- Baseline is exact public `0.5.9`, tag `0.5.9`, peeled commit `fbda0b706b20d7465b5e00f39aa6f68ed300fc7c`, and released `main.js` SHA-256 `fea947ac02dde39457fd18227f271b3773500a680f882df79db30be3b2bc50bf`.
- Exact `0.5.9` passed all 66 released checks and its production build.
- The new regression first proves the complete account-card, label, search, and rule-classification result, including a label-only uppercase-`.MD` account note. It then requires one account scan. Exact `0.5.9` failed only that final operation gate with three Markdown-list calls instead of two; it also performed four account metadata reads instead of two.
- Version `0.5.10` passes the regression with the required snapshot-selection traversal plus one account traversal and one metadata read per account note.
- An independent comparison executed the actual released and candidate plugin classes across 2,001 deterministic scenarios containing 7,212 account-path entries. Dashboard models matched exactly in every scenario.
- Across those scenarios:
  - Markdown-list calls fell from 6,003 to 4,002;
  - metadata reads fell from 18,833 to 11,621;
  - snapshot reads remained exactly 1,470.
- Targeted cases covered account sorting, duplicate IDs and paths, label-only notes, `.md`/`.MD`, `accountName`/`title`/filename fallbacks, plain unusual frontmatter values, masks and institutions, balances, holdings, missing account notes, transaction labels and search text, and account-based rule classification.
- A controlled fixture containing 20,000 account notes, 20,000 unrelated Markdown files, and 4,000 transactions ran for 25 alternating rounds:
  - median model-build time: 58.064 ms → 53.437 ms, 7.97% faster;
  - p95: 62.220 ms → 59.846 ms, 3.82% faster;
  - Markdown-list calls: 3 → 2;
  - account metadata reads: 40,000 → 20,000;
  - identical output digest: `ee1663a6a57a6433d9e70d126c48b60a418522f71fa3889cc99e107b007bcf6c`.
- The production bundle shrank from 88,717 to 88,561 bytes. Runtime source grew by four lines while falling from 44,044 to 43,994 bytes; the separate rescan helper was removed.

## Reliability and concurrency

- A failure from the removed third Markdown-list call or second metadata read can no longer fail an otherwise complete model. There is no retry or fallback route.
- Released `0.5.9` could combine an old account card with a newly renamed transaction label if account metadata changed while transaction notes were being read. Version `0.5.10` keeps the card and label from the same synchronous account scan.
- Account metadata changes already trigger the dashboard's coalescing refresh path. A concurrent rename therefore produces a coherent earlier snapshot followed by a coherent updated snapshot, instead of a mixed model.
- The label map is local to one model build and discarded afterward. This release adds no cache, timer, listener, persisted state, alternate data source, monkeypatch, or unsupported API.

## Validation

- The final versioned declared suite passed 67/67 checks, followed by TypeScript and the suite build.
- The independent adversarial review returned SHIP with zero model mismatches and identical supported error boundaries. It also confirmed that the optional private map avoids unused label work during Sync and is simpler than adding a compound return or persistent cache.
- A mandatory separate `npm run build` passed and deployed only byte-changed `main.js` and `manifest.json` to the isolated test runtime; `styles.css` remained byte-identical.
- Obsidian 1.12.7 was reloaded in `Obsidian Plugin Test Vault`. All five TPS Finances commands were registered, and the disconnected dashboard rendered with Rule, Budget, Connect, and Sync actions present.
- Plaid was not connected, Sync and all mutating actions were not invoked, and test-runtime `data.json` remained absent.
- Production was not accessed or promoted.
