# TPS Finances 0.5.3

This patch removes repeated categorization-rule preparation from the dashboard transaction loop while preserving every released classification result and fallback precedence.

## What changed

- Enabled categorization rules are filtered and ordered once per dashboard-model build.
- The resulting invocation-local classifier is reused across every historical transaction in that model.
- The existing `classifyTransaction` compatibility path retains its signature and behavior.
- No persistent cache, invalidation state, background work, settings field, or fallback route was added.

## Compatibility and migration

- This is a backward-compatible patch release with no migration.
- Rule enablement, priority/name ordering, stable ties, first-match behavior, manual overrides, additive rule tags, provider and uncategorized precedence, account matching, and inclusive amount boundaries are unchanged.
- Provider/uncategorized and account-search fallthrough remain supported product behavior rather than being removed as unsafe fallback logic.
- Settings, stored finance records, Plaid behavior, and the minimum supported Obsidian version of 1.12.0 are unchanged.

## Validation

- The complete versioned suite passed 25/25, including a deterministic assertion that rule filtering and ordering occur once and are not repeated while classifying transactions.
- Independent seeded differential testing matched the released classifier in 100,000/100,000 cases covering disabled and tied rules, tag-only winners, manual/provider/uncategorized precedence, Unicode, whitespace, account-search fallthrough, inclusive bounds, duplicate tags, `NaN`, infinities, and signed zero.
- A synthetic 20,000-transaction/120-rule classification-stage benchmark improved from about 200.87 ms before the change to 6.11 ms after it, approximately 32.9×. This is not an end-to-end dashboard timing claim.
- TypeScript and production esbuild passed. The required separate final build deployed byte-identical source/runtime artifacts to `Obsidian Plugin Test Vault`.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. The Finances command registered and the disconnected dashboard rendered without connecting Plaid, syncing, changing settings, or creating runtime state.
- Production was not accessed. This release is ready for the user's BRAT pull.

## Known limitations

- Vault reads, Markdown parsing, transaction date sorting, budget aggregation, and rendering are outside this optimization and still contribute to complete dashboard latency.
- An existing dashboard refresh arriving while a render is already active can wait until a later refresh trigger; this patch neither causes nor changes that behavior. Coalesced refresh delivery is a separate reliability improvement.
