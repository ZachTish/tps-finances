# TPS Finances 1.3.1

Fix Finance folder ignoring an empty value. In **Data & routing → Finance folder**, leave the field blank or enter `/` to write new finance notes and Bases directly at the vault root without category subfolders. The value persists after closing settings and reloading.

- Missing settings still default to `Finances`; named folders retain their existing layout.
- Existing accounts, transactions, and holdings remain in place and are reused by identity in root mode. This is not a bulk move.
- Root readers and generated Bases use finance properties, so ordinary notes do not become accounts, rules, budgets, or snapshots. Existing content survives destination collisions.
- Atomic line transactions retain the configured Daily Note/account-note routing. Plaid setup and credentials are unchanged.

Validation: all 114 tests passed, followed by a separate production build, deployment and reload in Obsidian Plugin Test Vault. UI QA cleared the field, verified persisted/reloaded root storage, and created a synthetic cash-account note directly at the root. Original settings were restored and the six QA outputs archived. No provider call or production installation occurred.

Known limitation: root mode discovers identified finance records throughout the vault. Duplicate identities and broken account links require repair rather than silent exclusion. The combined test-vault root dashboard reports an older cash fixture with a missing account link; isolated root read/write and dashboard regressions pass. Existing notes are not automatically moved.

Minimum Obsidian: **1.12.0**, desktop only. Plaid requires TPS Controller 1.3.0+ and its Obsidian 1.12.3 minimum. Patch version: backward-compatible fix for the destination setting and its storage behavior.

Tested in the test vault and ready for the user's BRAT pull. Production remains user-operated through BRAT.
