# TPS Finances 3.0.3 — Build Budget details when opened

Backward-compatible performance and interaction fix; minimum Obsidian remains 1.12.0.

The Budget renderer previously constructed every flexible transaction, category
editor and review movement even with its native disclosure closed. Expanding a
single budget row recalculated the plan and replaced the entire dashboard DOM.

Closed flexible transactions, Category limits and Review now contain only their
summaries and empty content containers. Opening builds only that disclosure;
closing removes its content. Row expansion updates its existing native button
and row-local detail container. Both reuse the already-calculated Budget model,
preserving surrounding controls, keyboard focus and scroll. Detached controls
cannot mutate the current expanded state, and repeated native toggle delivery
does no redundant work. The existing transient expanded set also retains Review
across data refreshes, month and currency changes while the view remains open.

Plan totals, filters, complete transaction lists, editing/add/open action owners,
month/currency choices and data refresh remain available. A refresh still loads
the latest model. Month/currency changes still recalculate from the loaded model.
One currency formatter is reused per Budget render. Calculation uses the existing
row amount map for identity membership, avoiding scans of a growing transaction
array. Both legs of a manual cash transfer still accumulate in one map entry;
internal movements net to zero with one source row.

No persisted setting, public API change, note migration, cache, vault listener,
provider request or background worker is introduced. Existing disclosure depth,
mobile CSS and native touch controls are unchanged. Large lists still render
fully when deliberately expanded; this fix does not add pagination or claim a
physical iPhone speed measurement.

## Validation

- Actual source renderers and calculations run in memory against a small DOM
  facade. Only Obsidian's view base/icons and model/action boundaries are stubbed;
  no fake Budget implementation is used. Synthetic fixtures cover 1,000 flexible
  purchases, a fixed target, category cap and two review movements, expansion
  bursts, control identity, focus/scroll, detached callbacks, native toggle
  repeats, refreshed amounts, month and currency selection. Real calculation
  cases cover 2,000 fixed movements, conflicting duplicate IDs and 100 manual
  cash transfers affecting both accounts in one savings target.
- The focused regression baseline on unchanged 3.0.2 passes 63/70. Seven failures
  demonstrate hidden construction, full-row repaint, stale controls, Review
  state loss and growing-array membership work. After the fix all 70 pass.
- The closed synthetic flow constructs 141 DOM-facade nodes including its
  stubbed Overview/loading stage, zero transaction buttons, one formatter and
  one Budget calculation pass. One fixed-row expansion creates six detail nodes,
  with zero additional model reads, calculations, root clears, full renders or
  formatter constructions. Disclosure bursts have the same zero-operation
  contracts outside their own content. These omit real Obsidian SVG/icon nodes.
- The versioned `TPS_NO_DEPLOY=1 npm test` passes 428/428 checks: 2 connection and
  426 Finance, no skips/failures. Its TypeScript-checked build reports
  `target=none reason=TPS_NO_DEPLOY`. An initial full run exposed a pre-existing
  sibling test's harness-prefix boundary after new tests were inserted before
  that boundary; moving those tests preserves the sibling harness unchanged.
- Foreground installed 3.0.2 baseline uses the real view prototype on an isolated
  synthetic model and appended QA region in the exact Test vault. It creates
  5,203 SVG-inclusive DOM nodes, 1,002 hidden transaction buttons and 1,024
  formatters on initial Budget render. Native Rent expansion performs another
  complete render/root clear and adds 1,025 formatter constructions; all sampled
  control identities change. These are operation counts, not mobile timings.
  All eight active consumers remain enabled. No real model reader/provider or
  mutating action is invoked; the original Finance error DOM is preserved and
  restored after cleanup.
- After Test-only deployment and targeted reload, loaded 3.0.3's actual view
  prototype/render queue is exercised on the same isolated synthetic model.
  Initial Budget constructs 173 SVG-inclusive nodes, zero transaction buttons
  and one formatter. Native Rent expansion has 179 nodes/one transaction button,
  keeps all five sampled controls and focus, and leaves cumulative model/render/
  root-clear/formatter counts at 1/1/1/1. Native collapse, Category/Food expansion
  and Flex disclosure perform no full render/model load/formatter construction.
  Category/Food expansion creates 1,000 visible transaction buttons; Category
  close removes them after native toggle delivery. Flex open creates 1,000
  visible buttons and 5,174 nodes while Category remains closed.
- Dynamic Review accessibility controls were unavailable to native automation.
  Review open/close, recorded Add/Edit/Open action callbacks, synthetic refresh
  and EUR selection therefore use guarded actual DOM/Console handlers. Review
  shows two rows; refresh changes the first purchase and shows $5,002 spent/$998
  remaining with Review still open. EUR shows €97 remaining and USD restores
  its totals. Mutating action owners record intended fixture calls only; no
  note, settings or provider write occurs. A repeated Budget-only render reads
  no model and uses one render/root clear/formatter. Overview retains its own
  existing formatting costs, which are outside this change.
- A real 380-pixel Test container has scroll width 380, three amount columns of
  approximately 83.33 pixels plus a 44-pixel edit column, and a 44×44 expansion
  button. The narrow screenshot/layout is visually checked. This is desktop
  narrow-container QA, not physical iPhone/iPad timing or touch acceptance.
  All eight active consumers remain enabled; their settings are untouched.
  Cleanup removes the owned QA region and temporary global/Intl instrumentation,
  restores the original real Finance error DOM and returns to ordinary Test UI.
  That real view still has its existing missing cash-account-link validation
  error; this release neither repairs it nor claims a populated-provider check.
- A separate `TPS_NO_DEPLOY=1 npm run build` passes after the documentation
  changes with `target=none reason=TPS_NO_DEPLOY`. The final ordinary
  TypeScript-checked build uses only the Test target and preserves the installed
  QA hashes below. Tested in the Test vault and ready for the user's BRAT pull;
  production is untouched.
