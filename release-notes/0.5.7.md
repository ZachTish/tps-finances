# TPS Finances 0.5.7

TPS Finances `0.5.7` is a backward-compatible dashboard and Sync performance/reliability release. It pins one invocation-local latest-snapshot document for balance and holding parsing, removing duplicate vault work and preventing cross-snapshot tearing while preserving every released feature and finance-data contract.

## What changed

- Dashboard model construction selects the latest snapshot once, captures its date before yielding, reads it once, and splits it into a readonly line collection once.
- Account balances and holdings parse that same document rather than independently selecting and reading the latest snapshot.
- Sync's pre-provider account/last-known-holdings read uses the same coherent-document path, so optional Investments preservation is pinned to one prior snapshot.
- Each affected operation removes one complete latest-snapshot vault traversal, one Obsidian `cachedRead`, and one document line split.
- The parsers are synchronous and contain no implicit I/O, retry, re-selection, or persistent cache path.

## Preserved behavior

- Latest-snapshot selection remains maximum frontmatter date, then maximum path for equal dates; missing dates still participate as empty selection keys.
- With no snapshot, account notes still load with null balances, frontmatter currency or USD, and no holdings.
- Duplicate balance records remain last-wins. Account frontmatter currency still outranks balance currency.
- Holding order, account-path matching, explicit holding currency, account-currency and USD defaults, explicit and snapshot-derived `asOf`, stale state, cost basis, and numeric handling are unchanged.
- A missing/deleted selected snapshot still propagates its read failure. The plugin does not retry or silently choose a different file.
- Commands, buttons, settings, Plaid requests, transaction routing, classification, budgets, Markdown formats, device state, and 0.5.6 action-refresh behavior are unchanged.
- No setting or data migration is required. Minimum supported Obsidian version remains `1.12.0`.

## Before and after evidence

- Exact released `0.5.6`: all 42 declared checks passed.
- A new real-main dashboard probe against released `0.5.6` observed three relevant `getMarkdownFiles()` traversals and two `cachedRead()` calls. By returning snapshot A on the first read and snapshot B on the second, it produced balance `100` with holding value `200`.
- Version `0.5.7` performs two relevant Markdown-file traversals, one snapshot read, and one line split; the same probe returns balance `100` and holding value `100`.
- The focused coherent-snapshot gate passes 4/4, including stable/no-snapshot semantics, rich currency/date/link/numeric cases, and one-attempt fail-closed read errors.
- The final declared suite passes 45/45, followed by TypeScript, the suite's production build, and the mandatory separate final build.
- Two independent adversarial reviews found no behavior, concurrency, error-propagation, or preservation blocker.
- Obsidian 1.12.7 reloaded the isolated test-vault runtime and rendered the disconnected Finances dashboard. No Plaid request, connection, Sync, setting change, note mutation, or production access occurred.

## Known limitations

- Live Plaid actions were not invoked during QA. Sync's one-document call path is source-contract checked; optional-Investments last-known-holdings behavior remains covered by the existing deterministic preservation tests.
- The snapshot document makes balance/holding parsing coherent with itself. It does not claim to make account metadata, transaction notes, rules, or Obsidian's metadata cache one atomic vault-wide snapshot.
