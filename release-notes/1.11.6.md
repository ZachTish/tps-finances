# TPS Finances 1.11.6

Dashboard refreshes use Obsidian's indexed atomic properties rather than reparsing every candidate's YAML. Newly created records appear after their properties are indexed; edits update through the existing metadata events and render queue. This adds no cache, watcher, timer, fallback parser, settings or note migration.

Sync, mutations, migrations, title review and zero-argument `api.getDashboardModel()` retain their current-source verification. Only the dashboard requests the internal metadata read mode. Mapped fields, full classification tags, duplicate identity guards, legacy inline discovery and atomic-record precedence remain. Snapshot and budget body reads are unchanged.

Backward-compatible performance patch; minimum Obsidian **1.12.0**.

## Validation

- Seven new regressions, five failed before the correction. All 115 focused and 305 declared tests pass with zero failures/skips; TypeScript and the separate production-mode build pass.
- Deployed only shipped artifacts to Obsidian Plugin Test Vault, followed by a named Finances-only reload. The other authentication panel was preserved.
- Actual installed readers, metadata events and dashboard DOM verified new transaction creation, amount edits, rename, classification removal/restoration, and legacy line removal/restoration. Each genuine change produced one model with correct rows; an unrelated rename produced none. Ten synthetic files across the before/after runs were directly archived with exact bytes intact. Five settings files matched during each run, and seven matched at final validation.
- Final installed source-API and metadata-display models had identical SHA-256 and included the same 1,694 transactions, 16 accounts and 13 holdings. Display eliminated 3,566 atomic source reads/parses per model: 14,803 cached reads became 11,237. The existing data API retained its source checks. All consumers remained enabled; no external provider action ran.

## Limits and handoff

The existing full-vault legacy body discovery still runs on real model loads. Indexed display can briefly lag a create/edit until Obsidian publishes its metadata; writer authority is unaffected. The final method comparison was hidden/unfocused. The dashboard was covered by an independent authentication panel, so API/DOM checks and operation counts do not establish foreground input latency, cold-process startup, physical iPhone behavior, production speed or 80% native parity.

Tested in the isolated test vault and ready for the user's **BRAT pull**. Publication is not production installation or device acceptance.
