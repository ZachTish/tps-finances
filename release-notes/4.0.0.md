# TPS Finances 4.0.0 — One primary record ID

Finance notes previously stored their own ID in a Finance-specific property
alongside GCM's shared primary ID. Transactions, accounts, rules and budgets now
write their existing ID value only under the identity property reported by GCM's
public `nativeRecords.getStorageProfile()` API. GCM owns that storage profile; Finance
does not add another identity setting. Without GCM, the standalone default stays
`tpsId`. An installed but unready or unsupported GCM blocks record work instead
of assuming its old saved format.

Nutrition properties remain separate and unchanged. Account foreign keys on
transactions/holdings, security references, links, filenames, provider state and
provider-to-local ID mappings keep their existing meaning. Holding edits preserve
independently assigned primary IDs and do not assign an absent one. Imported accounts are created with their final
fields, balances and primary ID, removing redundant post-create edits.

Readers accept existing whole-note legacy IDs and primary-only notes. The existing
owning edit removes a matching duplicate self ID beside the primary. Legacy-only
notes retain their one physical self ID during edits; identity-less existing notes
cannot acquire an ID through an ordinary edit. Display never rewrites notes.
Conflicting values, malformed IDs, case-variant duplicates or property collisions
fail before writes. Metadata preflight accepts primary-only transactions while
rejecting unrelated notes without reading their bodies. No-op imports still
perform zero transaction writes. The existing GCM readiness event refreshes a
mounted Finance view once when the public identity API becomes available; it does
no work for repeated announcements or absent consumers.

## Existing notes and compatibility

Update Finances on **every device** before creating or consolidating records.
Older 3.x versions cannot read primary-only transaction/account/rule/budget notes;
this intentional storage compatibility change requires major version 4.0.0.
Minimum Obsidian remains **1.12.0**. GCM must expose the public storage-profile
API; installed QA used GCM 8.2.0. No Companion transport schema is changed.

Use **Finances → Properties → Record IDs → Review existing IDs** to preview
existing notes, generated Base updates and conflicts. Nothing is changed until
confirmation. Equal duplicate self IDs are removed; legacy-only notes already have one own ID
and remain unchanged. Finance does not adopt arbitrary existing notes into the
shared namespace without GCM's mutation authority. The
original ID values, unrelated frontmatter, comments, line endings and body bytes
remain. Generated Base ID predicates accept the configured primary or the legacy own
ID, preserving visibility while old single IDs remain. Only exact recognized
plugin-generated Bases are remapped; customized
Bases stay untouched. A review can update generated Bases alone.

Confirmation repeats the source inventory and rejects changed configuration,
identities, duplicate ownership and malformed frontmatter before starting. Each
atomic note callback verifies the current full source and file object. Duplicate
removal changes no identity ownership. There is no global cross-file transaction:
completed targets remain if a later target changes; later unrelated edits stay
owned by their existing writers. An
interrupted operation requires another explicit review. No startup migration,
repair loop, new journal, cache, watcher, poller or reservation layer is added.

The settings destination map, default route, disclosure depth and persisted
settings keys/defaults stay unchanged. The new action is before property-name
editors in Properties. Its native review modal has Cancel, keyboard confirmation,
error announcements and focus restoration, using the existing mobile layout.

## Validation

- The final versioned declared suite passes **467/467** checks: 2 connection and
  465 Finance, no failures or skips. It includes TypeScript checking and a Test
  runtime build. Regression coverage exercises configurable storage keys, own vs
  foreign IDs, all record owners, kind-list metadata, pending-to-posted updates,
  manual transfers, same-mtime edits, rename/delete/replacement, stale rendered
  targets, GCM readiness, property-name migration, namespace conflicts and exact
  scalar/source preservation.
- Operation-count tests retain zero display body reads/writes, zero unchanged
  transaction write attempts and no classification decode for unrelated metadata
  candidates. Account creation prepares the final payload in one create. Mixed
  primary/legacy conflicts produce no record mutation. Finite migration tests
  cover 19 cases, including legacy-only preservation, configuration changes, generated
  Base-only changes and preservation of customized Bases.
- Foreground installed Test-vault QA loads the exact 4.0.0 bundle with the eight
  active consumers enabled. Normal native account and cash-transaction modals
  create one primary ID each. The transaction keeps its account foreign key;
  GCM recognizes the account's primary identity. Safe synthetic classification
  and folder changes exist in memory only and are restored without saving or
  enabling outbound automation.
- The installed native migration preview/cancel/confirm flow uses a narrowed
  four-note source inventory, not the entire test vault. Two previews and the
  apply preflight perform 12 fresh reads and one write. Cancel performs no writes.
  Confirmation removes only the equal legacy ID line, preserving body bytes and
  separate calories, protein, carbs and fat fields. The resulting indexed model
  has one account, three transactions and the expected balance of 64 from an opening
  100 and three synthetic expenses of 12. The legacy-only transaction stays
  byte-identical and is included in that indexed result.
- All eight plugin `data.json` hashes remain unchanged. Original in-memory
  settings, active note and migration methods are restored; temporary globals
  and developer tools are closed. Four final fixture notes are moved directly from
  Inbox to `_archive/Finance ID Final QA 20261009`.
- A mandatory separate final `npm run build` performs TypeScript checking and
  deploys only to the Test runtime. The artifacts match the installed QA build.
  Production notes/settings/runtime are not changed. This release is tested in
  the test vault and ready for the user's BRAT pull; it is not production-installed
  or user-accepted. Production bank import, full-vault installed migration,
  cold-start responsiveness and physical iPhone interaction remain unmeasured.
