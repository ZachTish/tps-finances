# TPS Finances 0.5.8

TPS Finances `0.5.8` is a backward-compatible account-sync performance and reliability release. It discovers existing account notes once per provider batch and reuses each resolved file within that invocation, preserving all released finance features while eliminating repeated whole-vault lookup work and metadata-lag duplicate creation.

## What changed

- `upsertAccounts()` returns immediately for empty input, then builds one invocation-local, first-wins map for only the requested `financeAccountId` values and stops once all are found.
- Every provider account reads that map before considering a live lookup.
- An index miss retains one supported `Vault.getMarkdownFiles()` plus MetadataCache scan before creating a note, so initially unavailable metadata can still recover safely.
- The initial index replaces the first account's released lookup. Later indexed hits are revalidated against the current vault object and current ID after awaited work; a moved ID, deletion, or same-path replacement falls through to one live scan.
- A found or newly created note is cached in the invocation map after its frontmatter refresh, so duplicate provider input reuses the same file even before MetadataCache catches up.
- The index is discarded when the batch returns. There is no persistent cache, invalidation listener, timer, retry loop, monkeypatch, adapter mutation, or unsupported Obsidian API.

## Preserved behavior

- Existing notes are still owned by exact `financeAccountId`.
- If multiple account notes carry the same ID, the first note in Obsidian vault order still wins.
- Existing account note paths remain stable; genuinely new accounts still use the released derived name and unique-path collision behavior.
- Every input account still refreshes title, kind, institution, type, subtype, name, mask, currency, and ID frontmatter.
- Duplicate account IDs in one provider batch still resolve to one final ID/path entry and the last input still refreshes that same note.
- Commands, buttons, settings, Plaid requests and cursor behavior, device state, transaction and investment storage, routing, snapshots, classification, budgets, GCM/Daily Notes compatibility, and dashboard behavior are unchanged.
- No settings or data migration is required. Minimum supported Obsidian version remains `1.12.0`.

## Before and after evidence

- The untouched exact `0.5.7` source passed all 45 declared tests, TypeScript, and its production build.
- Before the source change, both new executable account-upsert probes failed:
  - 120 existing accounts caused 120 complete Markdown-list traversals rather than one.
  - after correctly recovering an existing account whose metadata appeared following earlier awaited work, repeated new-account input performed another live scan and created a second note while the first new note's MetadataCache entry was still empty.
- On an identical synthetic fixture containing 20,000 unrelated Markdown files and 120 existing account notes, 30 complete batch upserts measured:
  - exact `0.5.7`: 3,600 Markdown-list calls, 217,800 account metadata reads, 12.120 ms median, 12.889 ms p95;
  - final `0.5.8`: 30 Markdown-list calls, 7,170 metadata reads, 0.144 ms median, 0.798 ms p95.
- This is a 98.8% median reduction at the isolated account-upsert lookup seam. Structural call counts are the deterministic result; wall time depends on vault size and device.
- The focused final gate passes 4/4 and proves first-note-wins ordering, all 120 returned paths, every refreshed frontmatter field, zero-work empty input, all-new scan parity, live metadata recovery after awaited work, one-note reuse for duplicate new input, moved IDs, and same-path replacement.

## Validation

- The final versioned declared suite passed 49/49 checks, followed by TypeScript and the suite's production build.
- An independent adversarial review rejected the eager first draft, then confirmed the final empty/input budget, requested-ID early stop, post-await current-file validation, and invocation-local duplicate reuse as ship-worthy.
- A mandatory separate final `npm run build` passed and deployed only byte-changed plugin artifacts to the isolated test runtime.
- Obsidian 1.12.7 was reloaded in the isolated test vault and rendered the disconnected Finances dashboard with its commands registered.
- Test-runtime `data.json` remained absent.
- No Plaid request, connection, Sync, setting change, finance-note mutation, or production access occurred during UI QA.

## Known limitations

- Live Plaid Sync was not invoked during QA. The complete storage path is exercised through the bundled real `FinanceStore` with a deterministic Obsidian vault/metadata harness.
- The invocation index is intentionally not retained across Syncs; persistent caching would require rename, delete, and metadata invalidation state.
- The miss-only live scan remains because removing it would make a temporarily incomplete MetadataCache capable of producing duplicate account notes.
