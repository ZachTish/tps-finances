# TPS Finances 1.11.4

Opening **Log cash transaction** loaded the complete dashboard solely to obtain account choices. That also inspected transactions, holdings, rules and budgets and calculated balances the form never used.

The command now validates the property configuration and uses the existing snapshot/account readers directly. Account order, names, currencies, paths and eligibility are preserved. The existing manual writer still validates current source before saving, and a successful record still refreshes the dashboard. Full dashboard reads are unchanged where the complete model is required.

This is a backward-compatible patch with no new cache, watcher, timer, retry, recovery logic, setting, schema or API. No migration is required. Minimum Obsidian: **1.12.0**.

## Validation

- Six focused regressions exercise the actual command method and manual writer with mocked account/modal boundaries. Four failed before correction. Coverage includes 20 open/cancel operations, account eligibility, configuration/snapshot errors, independence from unrelated transaction-model failures, successful saving and failed validation without partial writes.
- 45 focused checks and all 286 declared tests pass, with zero failures or skips. A pre-existing source-inspection test was corrected to inspect only the dashboard method rather than also counting adjacent commands. TypeScript and the separate production build pass.
- Test-vault deployment and named reload verified version 1.11.4 with byte-identical plugin settings. Final documentation build retained the tested runtime artifacts.
- Installed command before/after: dashboard loads **1 → 0**, cached note reads **14,730 → 0**, Markdown enumerations **7 → 2**. Both runs discovered the same 16 accounts; an order-preserving hash of every form-consumed account field matched exactly. No note mutations occurred, five monitored plugin settings files stayed unchanged, and all probes were removed.

The installed API probe used actual snapshot/account readers, then replaced the account list with an empty list at the presentation boundary to suppress opening a modal while another window had focus. This verifies the data-preparation work and account projection, not actual modal UI, cancellation gestures or opening latency. The test vault used atomic-note storage; the save path was tested separately with the real writer in the automated suite. All consumers remained enabled. Baseline trace-wide raw reads included background work and are not attributed to Finances. Physical iPhone, true cold-process startup, production speed and the broader native-performance target remain unverified.

Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. Production installation and device acceptance are separate and are not claimed.
