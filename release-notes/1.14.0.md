# TPS Finances 1.14.0 — Optional atomic-note-only discovery

Finance can now skip its vault-wide legacy inline transaction scan when the user explicitly selects **Data & routing → Transaction discovery → Atomic notes only**. The existing **Include inline entries** behavior stays the default. Before enabling the faster mode, Finances freshly audits all Markdown files and blocks on active `[financeId::` markers, including malformed or duplicate entries. It excludes only a verified converted transaction's original line retained in its `migrationSource` property; extra markers still block. Conversion stays an explicit, separate action. A failed audit leaves the old mode active; after a settings-write error, Finances reads back whichever mode reached disk. Switching to Atomic line restores inline discovery.

No notes are converted or repaired automatically. Existing atomic transaction filenames already contain their stable IDs, so no filename migration is needed. If an older plugin, another device or an external tool later writes an inline transaction, select Include inline entries to make it visible. Atomic notes only is an explicit format contract, not a continuing monitor.

Display-mode discovery conservatively skips body reads for notes Obsidian has indexed solely as ordinary headings/paragraphs. Ambiguous, unindexed, YAML, code and list notes still receive legacy body reads when inline discovery is enabled. Mutations verify current source at their write boundary. Vault-root atomic discovery reads candidates lacking metadata, since their filenames can be edited; a wholly unindexed root requires a full candidate read. Before creating a missing ID, a root write batch checks otherwise excluded note sources once, preventing a duplicate creation when metadata is stale. Ordinary root reads can still omit arbitrary-name notes with stale metadata that lacks finance hints, and a hidden duplicate of an already indexed ID remains undetected until metadata updates. Vault-root budget discovery remains another body-read cost. Minimum Obsidian: **1.12.0**. Tested in **Obsidian Plugin Test Vault** for the user's BRAT pull; production has not been modified.

## Validation

- The final declared test suite passed **336 checks** (2 connection checks plus 334 plugin checks), with no failures or skips. TypeScript passed. Focused tests cover activation audit, converted-note provenance, extra/malformed markers, interrupted conversion, shared-cycle settings-save failure, restoring inline discovery, stale and missing root metadata, duplicate atomic identities, and source/display operation counts.
- In a synthetic atomic-only run with 1,024 unrelated Markdown files, the source transaction reader cached-read one atomic note and display read zero note bodies; neither wrote a note. A mixed default-discovery fixture used 2,580 reads across 20 display models versus 5,140 without the conservative metadata preflight. A completely unindexed root still required 129 candidate reads in its 129-file test.
- The final build deployed only changed shipped files to the test vault; Hot Reload reloaded Finances 1.14.0. The installed settings control displayed its checking state, then refused activation for 10 remaining markers and returned to Include inline entries. The Finance `data.json` hash stayed unchanged, and no conversion or outbound sync ran.
- Foreground desktop first/repeated dashboard-open observations were approximately 1.37/0.92 seconds before and 1.62/0.97 seconds after. These include automation waits and show **no measured default-mode latency improvement**. Atomic-only mode could not be enabled in this vault while markers remain, so its installed speed and physical iPhone performance are unmeasured. The operation-count results above are synthetic, not installed-vault counts.
