# TPS Finances 1.14.1 — Indexed budget display

Finance dashboard refreshes now read indexed budget properties from Obsidian's metadata cache instead of opening each budget note body. A 1,025-note root fixture made zero body reads across 20 display loads, compared with 20 budget reads on the prior path. Source/API reads, the budget editor, and saves still use current note content. This is a backward-compatible performance fix with no settings or note migration; minimum Obsidian remains **1.12.0**.

The editor refreshes an existing budget before opening, rejects a changed budget identity at the same path, and keeps its revision check when saving. Source reads recognize legacy budgets encoded through Global Context Menu tags, including those without a budget ID. Notes with missing or ambiguous metadata still receive a content read. A root budget hidden behind stale, non-null ordinary metadata can remain undiscovered until Obsidian updates its index. Dashboard loads still enumerate the vault and inspect metadata for candidates, so this change does not remove all costs that grow with vault size.

## Validation

- The final declared suite passed **342 checks** (2 connection checks and 340 plugin checks), with no failures or skips. TypeScript passed. Focused tests cover indexed/mapped/GCM budgets, no-ID legacy budgets, immediate root creation, missing metadata, current-source edits, same-path identity changes, revision-guarded saves, and separate scan/read/write counts.
- In the 1,025-note fixture, 20 display loads made 20 Markdown enumerations, 20,500 metadata lookups, **zero note-body reads**, and zero writes; 20 current-source loads read the one budget body 20 times. A mixed 65-candidate missing/ambiguous fixture kept 65 body reads per display load. These are synthetic operation counts, not installed-vault timings.
- The final build deployed Finance 1.14.1 to **Obsidian Plugin Test Vault** and Hot Reload loaded the dashboard and Budget tab. Their visible totals were preserved; Finance `data.json` stayed byte-identical. No provider sync, note conversion, or real budget save ran.
- Foreground Budget-tab observations were about 0.97/0.42 seconds before and 0.70/0.67 seconds after for first/repeated switches. They include automation waits and do **not** establish a general speed gain. Physical iPhone behavior and a real budget edit remain unverified. Tested in the test vault for the user's BRAT pull; production was not modified.
